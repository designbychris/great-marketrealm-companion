# Phase III.M.6A — The Native Workshop

Phase III.M.6A establishes a native application workspace without replacing the Pocket Companion or creating a second character system.

## Decision

The workshop uses **Capacitor 8** as the stable native runtime. The existing Pocket Companion is web-first and already has a mature HTML/CSS/JavaScript experience; Capacitor lets the project preserve that investment while adding Android and iOS projects and native APIs later.

Capacitor 9 is intentionally not used while it remains a prerelease line. Capacitor 8 requires Node.js 22 or newer. iOS generation is prepared for Swift Package Manager.

## Authority boundary

GMRC remains authoritative.

- Native code must not create a second character database.
- The III.M.5C bridge contract remains version 1.0.
- Character and REST payloads are not approved for offline caching.
- Offline character writes remain prohibited.
- Native authentication is deliberately deferred to III.M.6B.
- The production app must not simply point Capacitor's `server.url` at the live WordPress application. The shipped shell is local; authenticated transport will be designed explicitly in III.M.6B.

## Workspace

`native/pocket-companion/` contains the native shell source and Capacitor configuration. Generated `android/` and `ios/` projects are not included in this phase because they should be generated by the matching Capacitor CLI on a development machine and then committed once verified.

The provisional application identifier is `uk.co.greatmarketrealm.pocket`. It can still be changed before the native platform projects are generated and before store registration.

## Android workshop

From `native/pocket-companion/`:

```bash
npm install
npm run build
npm run cap:add:android
npm run cap:open:android
```

The first Android build should display the local **Native Workshop** screen only. It must not fetch characters or ask for GMRC credentials yet.

## iOS workshop

When the Mac/Xcode environment is ready:

```bash
npm install
npm run build
npm run cap:add:ios
npm run cap:open:ios
```

The iOS project is configured to use Swift Package Manager when generated.

## Next phase

III.M.6B — The Guild Gate Native will design and implement the authentication/session handoff required for a native origin to communicate safely with GMRC. That phase must resolve the III.M.5C contract's current same-origin WordPress cookie + REST nonce boundary before character data is fetched by the native shell.
